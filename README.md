# Eduson Kids — платформа онлайн-школы

Внутренняя платформа онлайн-школы **Eduson Kids**: учёт учеников и групп, расписание и
посещаемость, продления, задачи, отчёты, база знаний. Два кабинета — администратора/менеджера
и преподавателя — с единым входом и обязательной двухфакторной аутентификацией для персонала.

Платформа заменяет прежнюю систему школы («OKK · Реестр», Express + SQLite). Кодовая база —
форк платформы школы KOTOKOD, данные Eduson перенесены на её модели.

> **Статус:** в разработке, работает локально. Боевого развёртывания новой платформы пока нет.

## Возможности

- **Учебная часть** — ученики, группы, преподаватели, направления, продления (CRM-воронка), задачи.
- **Занятия** — уроки и посещаемость, доп.уроки (отработки), календарь, план занятий с переносами
  и заменами преподавателя.
- **Финансы** — абонементы, расчёт баланса и выручки по FIFO, зарплата преподавателей.
- **Система** — Wiki (база знаний), отчёты с выгрузкой в Excel, архив, учётки и роли,
  журнал информационной безопасности, журнал изменений с откатом, уведомления.
- **Кабинет преподавателя** — свои группы, календарь, запись урока, история, зарплата.
- **Вход** — единая страница с выбором роли, 2FA (TOTP или код на почту), приглашения по ссылке.

## Стек

| Слой | Технологии |
|---|---|
| Бэкенд | Python 3.11, Django 5.1, Django REST Framework, SimpleJWT (HttpOnly-cookie), django-pghistory |
| База данных | PostgreSQL 15 |
| Фоновые задачи | Celery + Redis (необязательны: без Redis всё работает синхронно) |
| Фронтенд | React 19, TypeScript, TanStack Query 5, React Router 7, Vite |
| Веб-сервер | nginx (статика SPA, CSP, проксирование API) |

Визуальный язык — монохромный, шрифты Geist / Geist Mono (раздаются с того же origin).

## Быстрый старт (локально)

Требуется: Python 3.11, Node.js 20+, PostgreSQL 15; для полного стенда — nginx.
Команды даны для Windows (Git Bash / PowerShell); на Linux/macOS пути `.venv/bin/...`.

1. **Окружение Python**

   ```bash
   python -m venv .venv
   .venv/Scripts/python -m pip install -r journal_django/requirements-dev.txt
   ```

2. **Конфигурация** — скопировать образец и заполнить:

   ```bash
   cp .env.example .env
   ```

   Минимум: `DATABASE_URL` (база `eduson`) и `SECRET_KEY`. Все переменные описаны в `.env.example`.

3. **База данных**

   ```bash
   createdb eduson
   cd journal_django
   ../.venv/Scripts/python manage.py migrate
   ```

4. **Первая учётка (суперадминистратор)** — команда печатает ссылку-приглашение на 48 часов,
   по ней задаётся пароль и настраивается 2FA:

   ```bash
   ../.venv/Scripts/python manage.py bootstrap_admin --email you@example.com
   ```

5. **Сборка фронтенда** (собранные файлы в git не хранятся):

   ```bash
   cd frontend/admin-src && npm install && npm run build
   cd ../teacher-src && npm install && npm run build
   ```

6. **Запуск**

   ```bash
   cd journal_django
   ../.venv/Scripts/python manage.py runserver 127.0.0.1:8100
   ```

   В отдельном окне PowerShell — локальный nginx (раздаёт SPA с теми же заголовками, что в бою):

   ```powershell
   ./deploy/nginx/local/start-local-nginx.ps1
   ```

   Платформа открывается на <http://127.0.0.1:8180/>.

Для правки фронтенда с горячей перезагрузкой — `npm run dev` в `admin-src` (порт 5183) или
`teacher-src` (порт 5184); API проксируется на runserver `:8100`.

### Перенос данных из старой системы

```bash
PYTHONUTF8=1 ../.venv/Scripts/python manage.py import_eduson <путь к SQLite> --dry-run
```

`--dry-run` проверяет перенос без записи. Источник открывается только на чтение.
Файл базы старой системы содержит персональные данные и в репозиторий не кладётся.

## Тесты

```bash
cd journal_django
../.venv/Scripts/python -m pytest -q
```

- Тесты работают только с отдельной базой `eduson_test`: защита в `config/settings/test.py`
  не даст запустить их против рабочей базы.
- Запускайте **полный** набор: часть приложений использует общую тестовую базу, часть
  пересоздаёт свою, и прогон по частям даёт ложный результат.
- Пересоздать тестовую базу из миграций — `scripts/recreate_test_db.sh`.
- Фронтенд проверяется проверкой типов и сборкой: `npm run typecheck`, `npm run build`.

## Безопасность

- JWT только в HttpOnly-cookie, CSRF на всех изменяющих запросах, 2FA обязательна для персонала.
- Доступ проверяется на API: у каждого представления явный `permission_classes`.
- CSP `script-src 'self'` — никаких inline-скриптов.
- Ограничение частоты запросов на входе, кодах и сбросе пароля.
- Секреты — только в `.env` (не хранится в git). Персональные данные учеников, дампы и копии
  баз в репозиторий не попадают.

Подробный свод правил — [`docs/security-guidelines.md`](docs/security-guidelines.md).
Нашли уязвимость — сообщите владельцу репозитория напрямую, не через публичные issues.
