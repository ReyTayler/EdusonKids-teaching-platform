# Telegram-бот платформы Eduson Kids

Присылает преподавателям напоминания о занятиях.

---

## Что делает бот

**Источник правды один — журнал** (Django + PostgreSQL). Менеджер работает только в нём,
а рассылку журнал ведёт сам, напрямую через Telegram Bot API.

Боту остаются две роли:

1. **Отвечать на три команды** преподавателю.
2. **Сообщать журналу, какому Telegram-нику соответствует числовой `chat_id`.** По `@нику`
   Bot API в личку писать не умеет, а `chat_id` администратор глазами не видит. Как только
   человек написал боту хоть что-нибудь, его аккаунт появляется в журнале в списке для привязки.

Собственной базы, ролей и планировщика у бота нет.

---

## Что приходит преподавателю

Рассылает **журнал**, не бот. Здесь — для понимания, что увидит человек.

| Когда | Что | Куда |
|---|---|---|
| 8:00 | Список занятий на сегодня, с пометками «замена» и «доп.урок» | личка |
| 21:00 | Незаполненные отчёты по проведённым занятиям | личка |
| сразу | Назначен / отменён доп.урок | личка + общий чат |
| сразу | Перенос занятия, отмена занятия | личка + общий чат |
| сразу | Назначена или снята замена — уведомляются обе стороны | личка + общий чат |

Email-писем преподавателям нет. Чтобы уведомления начали приходить, администратор должен
привязать преподавателя к его Telegram-аккаунту в журнале (карточка преподавателя).

## Команды

| Команда | Описание |
|---|---|
| `/start` | Приветствие |
| `/help` | Список команд |
| `/my` | Мои занятия на ближайшую неделю |

Команды работают **только в личных сообщениях** — в групповом чате бот их игнорирует.

## Переменные окружения

Образцы: для Docker — `deploy/docker/bot.env.example` (на сервере файл `bot.env` создаёт
`deploy-staging.sh sync`); для локального запуска без Docker — `.env.example` (ниже).

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен от @BotFather. **Равен `TELEGRAM_BOT_TOKEN` журнала** |
| `BOT_SERVICE_TOKEN` | Общий секрет с журналом (заголовок `X-Bot-Token`), должен совпадать |
| `JOURNAL_API_URL` | Адрес журнала. Локально `http://127.0.0.1:8100`, в Docker `http://app:8000` |
| `JOURNAL_HOST` | Домен из `ALLOWED_HOSTS` журнала (в Docker); локально пусто |
| `TIMEZONE` | Таймзона отображения времени, по умолчанию `Europe/Moscow` |
| `LOG_LEVEL` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |

## Запуск в Docker

Бот — сервис `bot` в `deploy/docker/compose.*.yml`, переменные берёт из файла `bot.env`
(по образцу `deploy/docker/bot.env.example`; на сервере файл создаёт `deploy-staging.sh sync`).
Бот ходит в контейнер журнала `http://app:8000` напрямую, минуя
nginx; наружу `/api/integrations/` закрыт (404). Логи пишутся только в stdout —
смотреть `docker compose logs -f bot`.

## Локальный запуск (без Docker)

```bash
cd platform/bot
py -3.11 -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt
cp .env.example .env      # заполнить BOT_TOKEN и BOT_SERVICE_TOKEN
.venv/Scripts/python main.py
```

Журнал должен работать (`runserver` на :8100).

**Ограничение:** одним токеном опрашивать Telegram (`getUpdates`) может только ОДИН процесс.
Пока бот работает на сервере, локально нужен второй, тестовый бот со своим токеном.

## Тесты

```bash
.venv/Scripts/python -m pytest -q
```

## Диагностика

**Преподаватель не получает уведомлений.** Смотреть в журнале: раздел «Уведомления» показывает
доставку со статусами и текстом ошибки. Частые причины: аккаунт не привязан к преподавателю;
человек заблокировал бота; не работает Celery beat журнала.

**`/my` отвечает «аккаунт не привязан».** Администратор ещё не выбрал этот Telegram-аккаунт в
карточке преподавателя. Аккаунт появляется в списке только после первого сообщения боту.

**В логах бота HTTP 400 от журнала** — `JOURNAL_HOST` не совпал с `ALLOWED_HOSTS`.
**HTTP 401/403** — разошёлся `BOT_SERVICE_TOKEN` между бот-окружением и журналом.
