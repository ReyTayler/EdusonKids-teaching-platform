# Настройка мотивации — перенос UX в Eduson

Дата: 2026-11-23.

## Что перенесено

Применена структура интерфейса, разработанная для KOTOKOD после сравнения CRM: действующие условия отдельно от истории, явные единицы оплаты, редактор с проверкой новых условий и списком изменений. Визуальный язык — Eduson: Geist, монохромный акцент, линии вместо теней, существующие токены и компоненты форм.

Внутри «Настройки → Мотивация» появились вкладки групповых, индивидуальных и персональных ставок. Выбор хранится в параметре `motivation` адреса. Форматы — представления одной версии ставок школы; серверный контракт и общее изменение версии сохранены.

Главный экран показывает ставку по умолчанию, собственные ставки направлений и наследуемые значения. Компенсация отмены и штраф вынесены в отдельные блоки. Версии раскрываются по запросу, прошлую можно скопировать в новую. Действующие и прошлые версии не получают кнопок исправления/удаления, если API помечает их неизменяемыми.

Редактор: период действия → базовые ставки двух форматов → исключения направлений → компенсация отмены → штраф. Справа — сводка введённых условий и изменения относительно выбранной версии; на телефоне она расположена после полей. Это сводка, а не второй калькулятор зарплаты. Нового API предпросмотра и клиентской копии движка не добавлено.

## Отличия от KOTOKOD, сохранённые при переносе

- Групповые и индивидуальные ставки входят в одну версию школы.
- Базовая оплата — фикс за занятие, без порога малой группы и особой ставки 45 минут.
- Ставка по направлению может наследоваться отдельно для каждого формата; пустые поля отправляются как `null`.
- Нет версии на дату занятия — начисление 0, без возврата к старому калькулятору.
- Правила компенсации отмен, персональные ставки и штрафы продолжает применять существующий движок Eduson.
- Начавшиеся версии защищаются существующим серверным правилом; фронтенд ориентируется на `editable` API.

## Производительность и безопасность

Используются прежние API и общий ключ TanStack Query. Данные ставок не запрашиваются на каждую строку. При выводе направлений применяется Map; подробности исторической версии монтируются только после раскрытия. Новых библиотек, сетевых сервисов и внешних ресурсов нет.

Права superadmin, CSRF, server-side валидация и журнал изменений сохранены. В браузерных проверках все API-ответы синтетические; реальные ставки и зарплаты не изменяются.

## Проверка

- TypeScript и production-сборка обоих SPA.
- `python scripts/qa/motivation_ui.py` через локальный nginx `http://127.0.0.1:8180`.
- UI-сценарии: три вкладки, наследование ставок, изменение обоих форматов в одном payload, направления, тип компенсации, штраф, ошибка сохранения и повтор, POST новой версии, PATCH будущей версии, копирование прошлой, отсутствие изменения прошлой, отсутствие ставок, ошибка загрузки и повтор, недоступность раздела менеджеру.
- Desktop/mobile, светлая/тёмная темы. Скриншоты с вымышленными данными: `artifacts/motivation-ui/`.

Локальная сборка обновлена; выкладка на staging/прод не выполняется в рамках этой задачи. Изменения за пределами `EdusonPlatform/` не требуются.

### Результат локальной проверки

Браузерный сценарий через nginx прошёл; итоговые JS/CSS по HTTP совпадают с локальной сборкой. Production-сборки обоих SPA проходят. Первый TypeScript-прогон обоих SPA прошёл. При повторном прогоне admin обнаружены дубли объявлений в параллельно изменённом `src/lib/shared-types.ts` (включая несовместимое объединение `RateVersionPayload` с полями другой схемы мотивации). Этот файл не изменялся в рамках переноса дизайна; проблема зафиксирована отдельно. Бэкенд мотивации не изменён, новые ставки не создавались.
